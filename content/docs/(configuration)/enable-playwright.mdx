---
title: Enable Playwright
---

Umami can use a remote [Playwright](https://playwright.dev/) browser to capture live screenshots of your pages,
which are used as the background overlay in heatmaps. Without it, heatmaps fall back to an rrweb-based overlay
when session replays are enabled, or display click and scroll data on a blank canvas.

## When to use Playwright

Playwright is useful when:

- You want heatmap overlays to reflect the current live state of your pages, rather than a replayed recording.
- You are not using session replays and still want a page background in your heatmaps.

Playwright is optional. The rrweb overlay (available when session replays are enabled) covers most use cases without any additional infrastructure.

> Playwright is not supported on serverless setups. Use the rrweb overlay instead.

## Usage

Set `PLAYWRIGHT_URL` to the WebSocket endpoint of a remote `playwright-core`-compatible browser.
If your provider requires authentication, append `?token=<TOKEN>` to the URL.

```dotenv
# Without authentication
PLAYWRIGHT_URL=ws://playwright:3000

# With token-based authentication
PLAYWRIGHT_URL=ws://playwright:3000?token=YOUR_TOKEN
```

### Docker Compose example

Add a Playwright service to your existing Docker Compose setup and set `PLAYWRIGHT_URL` on the Umami service:

```yaml
playwright:
  image: mcr.microsoft.com/playwright:v1.60.0-noble
  restart: always
  init: true
  ipc: host
  user: pwuser
  working_dir: /home/pwuser
  command:
    - /bin/sh
    - -lc
    - npx -y playwright@1.60.0 run-server --port 3000 --host 0.0.0.0 --token ${PLAYWRIGHT_TOKEN}

umami:
  environment:
    PLAYWRIGHT_URL: ws://playwright:3000?token=${PLAYWRIGHT_TOKEN}
```

Set `PLAYWRIGHT_TOKEN` to a secret value of your choice in your environment or `.env` file.
