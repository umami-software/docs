---
title: Heatmaps
---

*Available since v3.2.0*

**Heatmaps** visualize where visitors click and scroll on your pages — giving you an at-a-glance view of engagement patterns without watching individual replays.
Use heatmaps to identify which elements attract the most attention, discover dead clicks, and understand how far down the page visitors actually scroll.

## Enabling Heatmaps

Log into Umami and click on **Websites** in the sidebar.

![image](/images/docs/navbar.png)

Click on the **Edit** button for the website you want to edit.

![image](/images/docs/website-edit.png)

Navigate to the **Replays & Heatmaps** section and enable the **Heatmaps** toggle.

![image](/images/docs/heatmap-edit.png)

| Option | Description | Default |
| --- | --- | --- |
| Heatmap Sample Rate | Fraction of sessions to include in heatmap data, from `0` to `1`. | `0.15` |

Add the recorder script to your site. This enables heatmap event collection.

```html
<script
  defer src="http://localhost:3000/recorder.js"
  data-website-id="my-website-id"
></script>
```

> **Notes**
>
> - Heatmap data is only collected from sessions recorded after enabling the feature.
> - Heatmaps are generated from aggregated session data — no individual session is identifiable.

## Page Overlay

The heatmap overlays click dots or scroll bands on top of a background snapshot of your page.
There are two ways to get a background snapshot, depending on your setup.

### rrweb overlay

If you have **Replays** enabled, Umami automatically extracts a representative frame from replay recordings and uses it as the heatmap background. No additional configuration is required — the overlay appears as replay data accumulates.

### Playwright overlay

If you have a separate Playwright container, set `PLAYWRIGHT_URL` to connect to it. Umami will use Playwright to take a live screenshot of each page as the background.

```bash
# Self-hosted Playwright container
PLAYWRIGHT_URL=ws://playwright:3000

# With token-based authentication (e.g. browserless)
PLAYWRIGHT_URL=wss://chrome.browserless.io?token=YOUR_TOKEN
```

`PLAYWRIGHT_URL` must be a WebSocket endpoint accepted by `playwright-core`'s `chromium.connect()`. If your provider requires authentication, append `?token=<TOKEN>` to the URL.

> `PLAYWRIGHT_URL` is not supported on serverless setups.

> If neither session replays nor `PLAYWRIGHT_URL` are configured, heatmaps still show click and scroll data — just without a page background.

## Accessing Heatmaps

Navigate to a website and click the **Heatmap** tab.

![image](/images/docs/heatmap-pages.png)

Use the **Pages** dropdown to select the page you want to inspect.

![image](/images/docs/heatmap-clicks.png)

The heatmap overlay is rendered on top of a snapshot of the page when one is available.

## Heatmap Types

Use the type selector to switch between views.

![image](/images/docs/heatmap-scroll.png)

| Type | Description |
| --- | --- |
| Click | Shows where visitors click. Highlights high-engagement elements and dead clicks. |
| Scroll | Shows how far down the page visitors scroll. Useful for identifying content below the fold that goes unseen. |
