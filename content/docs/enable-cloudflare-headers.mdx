---
title: Enable Cloudflare headers
description: Configure Cloudflare and your self-hosted reverse proxy to pass visitor location headers to Umami so it can record region and city data.
---

This guide applies to **self-hosted Umami** when analytics collection requests pass through Cloudflare to your Umami server. Enabling Cloudflare on the tracked website alone does not send its location headers with separate analytics requests.

For **Umami Cloud**, see [IP handling and reverse proxies](/docs/metric-definitions#reverse-proxies-and-umami-cloud). Cloud manages its collection infrastructure; the Nginx configuration and runtime variables below are not Cloud account settings.

Umami can use Cloudflare-provided country, region, and city headers. Cloudflare's [Add visitor location headers transform](https://developers.cloudflare.com/rules/transform/managed-transforms/reference/) supplies additional location information.

## Steps

1. Log in to the Cloudflare dashboard and select your account and website.

2. Go to Rules > Settings.

3. Go to the Managed Transforms tab.

4. Enable the **Add visitor location headers** setting.

Then, you'll have to proxy [the following headers](https://github.com/umami-software/umami/blob/aaa1f9dc58feafe6af54248c5f0611112786fddf/src/lib/detect.ts#L14C2-L18C5) to Umami:

- `CF-IPCountry`
- `CF-Region-Code`
- `CF-IPCity`

Only forward these headers from a trusted Cloudflare connection, and restrict access to the origin so clients cannot bypass that trusted proxy and supply their own headers.

For example, if you're using Nginx as a reverse proxy, you can add the following configuration:

```nginx
location / {
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Host $host;
    proxy_set_header CF-Connecting-IP $http_cf_connecting_ip;
    proxy_set_header CF-IPCountry $http_cf_ipcountry;
    proxy_set_header CF-Region-Code $http_cf_region_code;
    proxy_set_header CF-IPCity $http_cf_ipcity;
    proxy_pass http://127.0.0.1:3000;
}
```

## Force local geo database

Alternatively, when Cloudflare sends only the country but adding the visitor location
headers is not possible, you can set the `SKIP_LOCATION_HEADERS` runtime variable to `1`.
This disables header detection and forces the usage of the internal geo database for region and city resolution.

```dotenv
SKIP_LOCATION_HEADERS=1
```

The local database uses the IP available to Umami. It cannot recover an original visitor IP removed or anonymized by a proxy, and region or city data may be unavailable. See [location metrics](/docs/metric-definitions#location-metrics) for accuracy limits and the distinction between analytics records and operational logs.
