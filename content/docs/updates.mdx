## Source code

Make sure you are in the Umami project directory before running these commands.

Pull the latest changes from the Git repository:

```shell
git pull
```

Install any new or updated dependencies:

```shell
pnpm install
```

Rebuild the project:

```shell
pnpm build
```

Finally, restart the application:

```shell
pnpm start
```

If you are using a process manager like PM2, restart the process instead:

```shell
pm2 restart umami
```

## Docker

Pull the latest image:

```shell
docker pull docker.umami.is/umami-software/umami:latest
```

Then restart your container to use the new image.

If you are using Docker Compose, pull the latest image and recreate the containers:

```shell
docker compose pull
docker compose up --force-recreate -d
```

## Upgrading to v3.5.0

Check the following before you upgrade to v3.5.0:

- **Set `APP_SECRET`.** Umami no longer falls back to `DATABASE_URL` when `APP_SECRET` is missing, and will not
  start without it. The bundled Docker Compose file also refuses to start without it. If you never set it, see
  [APP_SECRET](/docs/environment-variables#app_secret) for how to keep existing logins and sessions working.
- **Use Node.js 20.19 or newer.** Node.js 22 LTS is recommended. This only applies when installing from source.
  The Docker image includes its own Node.js.
- **Password changes have moved** from **Settings > Profile** to **Settings > Security**.
- **The default password must be replaced.** If the `admin` account still uses the default password, you are asked
  to change it the next time you log in.
- **The public `/api/config` endpoint has been removed.**

This release adds the `27_add_error_tracking` PostgreSQL migration for [error tracking](/docs/error-tracking).
It runs automatically during `pnpm build` and when the Docker container starts.

## Refresh database statistics after upgrading

Major upgrades (such as moving to v3) run schema migrations that can leave PostgreSQL's query planner with stale statistics, making dashboard queries slower than expected on large instances. Run `ANALYZE` to refresh them:

```sql
ANALYZE;
```

This is safe to run on a live database and completes quickly. Afterward, dashboard queries should return to their expected speed.
